# 08 — 1.0.3 frame contract and API addendum

Status: patch over 05/07. Public `Cmd` topology is unchanged.

## Done-frame contract

Every worker `kind: "done"` frame includes:

```text
{ v: 1, id, kind: "done", changedRows: Int, lastInsertRowId: String, ... }
```

`execute` fills `changedRows` / `lastInsertRowId` from SQLite. `open`, query
completion, `begin`, `commit`, and `rollback` emit `changedRows = 0` and
`lastInsertRowId = "0"`.

Parent Elm still decodes those two fields (and `columns` / `rows`) with
`oneOf [ field, succeed default ]`. An absent field is not a protocol failure.
`Decode.field` alone is not used: it fails on a missing key before an inner
default can apply. That is the 1.0.2 query/transaction `ProtocolFailure
"invalid supervisor response"` defect.

## Begin failure

If `begin` does not decode as success, the parent sends `rollback` before
settling the transaction. A SQLite-level begin error is not in a transaction;
rollback is ignored if it fails. The worker is never left inside a transaction
after a failed `transaction` command.

The kernel assigns sequential request ids (`handle.next`). Multi-step
transactions and the extra rollback request stay in protocol order.

## Public API added in 1.0.3

```elm
errorKind : Error -> ErrorKind
errorMessage : Error -> String
errorCode : Error -> Int

transactionAndThen :
    (a -> TransactionProgram e b)
    -> TransactionProgram e a
    -> TransactionProgram e b

close : Database -> (Result Error () -> msg) -> Cmd msg
```

`close` disconnects and unrefs the supervisor child for that database path
(`path|rw` and `path|ro`). Queued work is `CancelledBeforeDispatch`; an
in-flight operation is interrupted. After `close`, a worker program can exit
without `process.exit`.

Sibling commands from one `Cmd.batch` are admitted FIFO (the manager reverses
the effect-manager list).

## Gate

`node scripts/schelm-gate.cjs` compiles `fixture-apps/schelm-gate` with
`schelm make --no-wire` in debug and `--optimize`, using a temporary
`SCHELM_HOME` (never `~/.schelm`). It runs `queryAll`, `queryOne`,
`queryMaybe`, `transaction` (execute then query), `Cmd.batch` order, and
`close` in both bundles and requires a natural process exit.
