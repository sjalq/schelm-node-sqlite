# 06 — Property, model, failure, and evidence plan

Status: executable acceptance plan for final design 05. Production implementation is complete only when this plan passes from the final commit.

## 1. Reproducibility and provenance

- normative toolchain: private Elm 0.19.2 compiler pinned commit, Node 24.4.1, built-in SQLite 3.50.2, Linux x64 and arm64;
- every randomized suite records master seed, sub-seed, shrink trace, Node/SQLite/compiler versions, architecture, and commit;
- CI default seeds are fixed; nightly adds random seeds and prints them before execution;
- every fixture process has a hard parent wall timeout and kill/reap assertion;
- generate provenance only after the final implementation commit: source hashes, assembled-kernel canonical hashes, compiler/node artifacts, package archive hash, test command/results, and platform facts;
- archive reproducibility builds twice from clean isolated homes and compares bytes;
- artifact gate proves feasibility/fault hooks and API-contract stubs are absent from production generated JS.

## 2. Pure Elm properties

Run `elm-test` with at least 2,000 fuzz cases/property in debug-generated test code.

### Constructors

- database path, SQL, timeout, collection/pool/meter bounds accept exactly documented domains;
- lone surrogate/NUL/oversized UTF-8 fail; constructor cost is O(input bytes);
- command/query are total descriptions and make no grammar/placeholder guarantee;
- canonical Int64: parse(print(x)) for min/max/generated hi-low model; reject signs, leading zeros, overflow, whitespace; checked Int conversion;
- Value binary model round trips NULL, full Int64, finite REAL bit patterns, Unicode TEXT, arbitrary BLOB.

### Decode

- identity/composition laws for `map`/`apply`/`andThen` where failure messages are normalized;
- map2…map8 equal nested apply;
- field/index path ordering; missing/ambiguous/negative/out-of-range errors;
- nullable accepts only NULL or underlying decoder;
- float vs number and exact integer conversion;
- oneOf deterministic first success, bounded branch/path failures;
- foldValues equals pure list fold and short-circuits first bounded domain failure;
- JSON recipe round trips generated `Json.Value` encoded as TEXT; malformed JSON is caller `Decode.fail`.

### Transaction program

- pure reference fold proves sequential continuation order and typed domain short-circuit;
- no public module exports resource ids/handles (API docs + compile-fail applications);
- transaction failure preserves arbitrary domain ADT unchanged;
- instruction meter stops exactly at limit without constructing instruction `limit + 1` effect.

## 3. SQL/autocommit differential

Generate SQL prefixes containing whitespace, comments, quote styles, semicolons, control words, malformed terminators, Unicode, and placeholders. Compare pure conservative classification to worker prepare facts. Required properties:

- lexical rejection has no false claim of SQLite validation;
- accepted tail either prepares as exactly one statement or worker returns typed `InvalidSql` before execution;
- placeholder mismatch is typed and no step occurs;
- manual transaction control and trigger-induced state drift is caught by physical invariant;
- `isTransaction` checks occur before/after prepare execution, every `next`, every `return`/reset, begin, rollback, commit;
- mismatch poisons generation, attempts rollback, closes, and never dispatches queued request to old generation.

Production fixture emits test-only ordered phase observations assembled from canonical source; artifact gate removes them from production.

## 4. Protocol properties: both hops

A pure Elm protocol model and production JS decoder consume identical generated byte streams.

- split every representative frame at every byte boundary; randomly coalesce frames;
- wrong magic/version/features/tag/flags/CRC/generation/id/length; noncanonical UTF-8/Int64/Value; partial EOF; trailing/duplicate/late frames;
- declared oversize rejected after fixed header before payload allocation;
- request id/generation never wrap or resurrect;
- accepted response requires exact full id tuple and expected state;
- fuzzer tracks peak retained bytes; endpoint never exceeds fixed header + negotiated inbound frame + one outbound credited frame;
- independent parent-supervisor and supervisor-worker credit models;
- no send without message+byte credit and pipe drain;
- credit replenishes only after local disposal and downstream acceptance/disposal;
- one query demand produces at most one physical next and one row;
- stalled parent, supervisor, and worker each produce bounded retention, no busy loop.

Seeds: fixed `0x53514C31`, `0x43524544`, `0x494E5436`, plus nightly random. At least 100,000 protocol traces/seed in Node property tests.

## 5. Parent Elm manager model

Generate traces over 200 logical caller sessions, 16 database keys, maximum 8 workers, queue/cancel/start/ready/dispatch/row/done/fail/poison/evict/death events.

Compare production effect manager state observations with a pure model:

- one in-flight/database;
- physical queue nodes equal live queued ids; no tombstones;
- ≤256/database, ≤1024 global, ≤8 workers;
- FIFO/database;
- deficit round-robin: an admitted ready ordinary request sees ≤7 other ready-database quanta before selection;
- finite exclusive quantum obeys instruction/row/wall meters;
- cancellation before dispatch has no worker effect;
- settled requests and resources are absent;
- stale/duplicate identities poison without insertion;
- no tick scans 200 sessions, all queues, or transcript-sized state.

Run 10,000 traces × 500 events with deterministic shrinkers. A 200-session scale fixture asserts constant worker/process cap, bounded queue rejection, and no starvation under finite workloads.

## 6. Real SQLite model tests

Use temporary real databases; compare generated operations to an in-memory Elm/JS reference map:

- insert/update/delete/select, NULL, Unicode, blobs, REAL, exact 64-bit boundaries;
- unique, primary, foreign-key, not-null, check, readonly numeric classification;
- queryOne/queryMaybe cardinality requests no more than two rows;
- queryAll iterates only, respects rows/scalars/text/blob/aggregate limits before IPC, and never invokes Node `all()` (positive trap fixture fails if called);
- duplicate column names and indexed decode;
- transaction success/domain failure/SQL failure/decode failure atomicity;
- migration list of single commands and `user_version` final command;
- external schema change and `SQLITE_SCHEMA` fail-closed generation behavior;
- WAL open/report/reopen, checkpoint coexistence, and no package WAL/SHM unlink.

Minimum 2,000 generated DB traces; fresh DB per trace group; deterministic SQL/value seeds.

## 7. Acknowledgement-cut failure matrix

For command, writable query, read-only query, transaction action, rollback, and commit inject death/cancel/protocol loss at:

1. queued;
2. sent parent→supervisor;
3. forwarded supervisor→worker;
4. before SQLite entry;
5. during SQLite;
6. after physical return;
7. after worker frame write;
8. after supervisor validation;
9. after parent boundary decode;
10. after parent Elm observation;
11. after application settlement.

Assertions:

- potentially mutating + dispatched + missing terminal Elm observation = uniform unknown outcome;
- writable iterator stays unknown until QueryDone/reset observed;
- read-only DB may return Interrupted;
- domain failure settles only after rollback observation;
- decode failure after SQL terminal observation is known DecodeFailed;
- no blind replay by manager;
- queued undispatched request may proceed on fresh generation preserving FIFO.

Each matrix cell runs debug and optimize workers with a 10-second hard timeout and process/fd residue check.

## 8. Crash, process, WAL, and busy tests

- kill worker in recursive query/open transaction: supervisor responsive, kill ladder bounded, rollback on reopen;
- kill parent while worker blocked: supervisor sees EOF, kills/reaps worker, removes ownership record;
- kill supervisor: parent backstop reaps owned group and rotates generation;
- stale record: absent parent + exact start identities reaped; pid reuse/mismatch/uid/executable ambiguity never signalled;
- SIGTERM-ignoring/blocking worker reaches SIGKILL rung;
- two database workers contend on WAL write; finite timeout yields numeric Busy/Locked, parent remains responsive;
- crash with WAL frames reopens through SQLite recovery; package never deletes WAL/SHM;
- conflicting immutable options reject;
- 200 caller sessions disconnect/cancel/restart while 8 workers active; no orphan, no >8 workers, queues remain physical-bound.

Linux `/proc` and process-group assumptions run on x64 and arm64 CI. Unsupported host fails closed.

## 9. RSS and performance gates

Measure cold and warm p50/p95/p99 with pinned hardware class metadata:

- supervisor+worker spawn/open/first query;
- persistent warm cron get/upsert/three-row list versus process-per-operation baseline;
- 8 databases and ninth waiting/eviction;
- 100k-row cursor throughput and parent/supervisor/worker peak RSS;
- SQLite sort/recursive/temp workloads exceeding soft/hard WorkerMemoryGuard;
- 25 ms RSS sampling overshoot distribution and kill latency;
- cancellation wall bound; idle eviction process/fd/RSS return.

Gates:

- warm cron median ≥5× faster than process-per-operation and zero warm spawns;
- protocol retained bytes within negotiated formula exactly;
- worker RSS is reported honestly, not asserted as hard capped; memory-guard kill occurs within sample interval + escalation budget, with measured maximum overshoot published;
- optional cgroup test proves `memory.max` only when capability is actually detected/reported;
- 100k rows do not scale retained protocol memory with row count;
- process/fd count returns to baseline after idle eviction.

Record baseline JSON under `tests/perf/baseline/<platform>.json`; threshold change requires explicit reviewed commit.

## 10. Debug/optimize and compatibility matrix

Build every public example, production worker, manager fixture, property fixture, and failure fixture in debug and `--optimize`; run identical semantic assertions. Initial supported host is exactly Node 24.4.1/SQLite 3.50.2. Candidate Node point releases run:

- option/BigInt/blob/error shape probes;
- statement reset/connection finalization;
- autocommit step/reset checks;
- protocol/process/crash suite;
- package archive and debug/opt parity.

Failure keeps the release unsupported; there is no fallback binding.

## 11. Cron and index package differentials

These run in the package repository before any harness integration.

### Cron first

Against cloned fresh/legacy DBs compare current cron-store JS and package adapter for schema/migration facts, WAL/NORMAL/busy settings, upsert/get/list order, null fields, JSON corruption policy, lock contention, restart, parent death, and unknown upsert outcome. Compare rows/PRAGMAs/typed outcomes, not English strings.

### Index second

Compare schema/FTS facts, quick_check, event/chunk/watermark transaction, long bounded scans, search rows/order inputs, busy/schema/corrupt facts, restart/WAL, and rebuild decision remaining outside package. Journals remain source of truth. No production dual writing.

Package adapters are test-only until independent package audit acceptance.

From clean checkout at final commit:
